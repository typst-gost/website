<span id="summary" />

*Добавлено в версии: 0.8.0*

Загружает модуль WebAssembly.

Полученный [модуль](/docs/typst/reference/foundations/module) будет содержать одну Typst-[функцию](/docs/typst/reference/foundations/function) для каждого экспорта функций загруженного модуля WebAssembly.

Плагины Typst WebAssembly должны следовать определённому [протоколу](#protocol). Чтобы работать как плагин, программа должна быть скомпилирована в 32-битную разделяемую библиотеку WebAssembly. Функции плагина могут принимать несколько [байтовых буферов](/docs/typst/reference/foundations/bytes) в качестве аргументов и возвращать один байтовый буфер. Как правило, их следует оборачивать в идиоматичные Typst-функции, выполняющие необходимые преобразования между нативными типами Typst и байтами с помощью [`str`](/docs/typst/reference/foundations/str#constructor), [`bytes`](/docs/typst/reference/foundations/bytes#constructor) и [функций загрузки данных](/docs/typst/reference/data-loading).

В целях безопасности плагины работают изолированно от вашей системы. Это означает, что печать, чтение файлов и подобные операции не поддерживаются.


## Чистота [#purity]

Функции плагина **должны быть чистыми:** вызов функции плагина не должен оказывать никаких наблюдаемых побочных эффектов на последующие вызовы плагина, и при одинаковых аргументах он всегда должен возвращать одно и то же значение.

Причина в том, что функции Typst должны быть чистыми (что является довольно фундаментальным для дизайна языка), а поскольку функции Typst могут вызывать функции плагина, это требование наследуется. В частности, если функция плагина вызывается дважды с одинаковыми аргументами, Typst может кэшировать результаты и вызвать вашу функцию только один раз. Более того, Typst может запускать несколько экземпляров вашего плагина в нескольких потоках без общего состояния между ними.

Typst не проверяет чистоту функций плагина (по соображениям эффективности), но вызов нечистой функции приведёт к непредсказуемым и невоспроизводимым результатам, и его следует избегать.

Тем не менее, изменяемые операции _могут быть_ полезны для плагинов, требующих затратной инициализации во время выполнения. Из-за требования чистоты такую инициализацию нельзя выполнить через обычный вызов функции. Вместо этого Typst предоставляет [API переходов плагина](#definitions-transition), который выполняет вызов функции, а затем создаёт производный модуль с новыми функциями, которые будут наблюдать побочные эффекты, произведённые вызовом перехода. Исходный плагин остаётся неизменным.

## Плагины и пакеты [#plugins-and-packages]

Любой код Typst может использовать плагин, просто включив файл WebAssembly и загрузив его. Однако, поскольку байтовый интерфейс плагина довольно низкоуровневый, плагины обычно предоставляются через пакет, содержащий плагин и идиоматичные функции-обёртки.

## WASI [#wasi]

Многие компиляторы используют [ABI WASI](https://wasi.dev/) по умолчанию или как единственный вариант (например, emscripten), что позволяет печатать, читать файлы и т. д. Этот ABI не будет напрямую работать с Typst. Вам нужно либо скомпилировать для другой цели, либо [заглушить все функции](https://github.com/typst-community/wasm-minimal-protocol/tree/main/crates/wasi-stub).

## Протокол [#protocol]

Чтобы использоваться как плагин, модуль WebAssembly должен соответствовать следующему протоколу:

### Экспорты [#exports]

Модуль плагина может экспортировать функции, чтобы сделать их вызываемыми из Typst. Чтобы соответствовать протоколу, экспортируемая функция должна:

- Принимать `n` 32-битных целочисленных аргументов `a_1`, `a_2`, …, `a_n` (интерпретируемых как длины, поэтому `usize/size_t` может быть предпочтительнее) и возвращать одно 32-битное целое число.
- Функция должна сначала выделить буфер `buf` длиной `a_1 + a_2 + ... + a_n`, а затем вызвать `wasm_minimal_protocol_write_args_to_buffer(buf.ptr)`.
- Первые `a_1` байтов буфера теперь составляют первый аргумент, следующие `a_2` байтов — второй аргумент и так далее.
- Теперь функция может выполнить свою работу с аргументами и создать выходной буфер. Перед возвратом она должна вызвать `wasm_minimal_protocol_send_result_to_host`, чтобы отправить свой результат обратно хосту.
- Чтобы сигнализировать об успехе, функция должна вернуть `0`.
- Чтобы сигнализировать об ошибке, функция должна вернуть `1`. Записанный буфер тогда интерпретируется как сообщение об ошибке в кодировке UTF-8.

### Импорты [#imports]

Модули плагинов должны импортировать две функции, предоставляемые средой выполнения. (Типы и функции описаны с использованием синтаксиса WAT.)

- `(import "typst_env" "wasm_minimal_protocol_write_args_to_buffer" (func (param i32)))`

  Записывает аргументы для текущей функции в буфер, выделенный плагином. Когда вызывается функция плагина, она [получает длины](#exports) своих входных буферов в качестве аргументов. Затем она должна выделить буфер, ёмкость которого не меньше суммы этих длин. После этого она должна вызвать эту функцию с `ptr` на буфер, чтобы заполнить его аргументами один за другим.
- `(import "typst_env" "wasm_minimal_protocol_send_result_to_host" (func (param i32 i32)))`

  Отправляет вывод текущей функции хосту (Typst). Первый параметр должен быть указателем на буфер (`ptr`), а второй — длиной этого буфера (`len`). Память, на которую указывает `ptr`, можно освободить сразу после возврата этой функции. Если сообщение должно интерпретироваться как сообщение об ошибке, оно должно быть закодировано в UTF-8.

## Функции [#functions]

### `transition` [#definitions-transition]

*Добавлено в версии: 0.13.0*

Вызывает функцию плагина, имеющую побочные эффекты, и возвращает новый модуль с функциями плагина, которые гарантированно наблюдают результаты изменяемого вызова.

Обратите внимание, что вызов нечистой функции через обычный вызов функции (без использования API переходов) запрещён и приводит к непредсказуемому поведению. Подробнее см. в [разделе о чистоте](#purity).

В приведённом ниже примере мы загружаем плагин `hello-mut.wasm`, который экспортирует две функции: функция `get()` извлекает глобальный массив в виде строки. Функция `add(value)` добавляет значение в глобальный массив.

Мы вызываем `add` через API переходов. Вызов `mutated.get()` на производном модуле будет наблюдать добавление. Тем временем исходный модуль остаётся нетронутым, как демонстрирует вызов `base.get()`.

_Примечание:_ Из-за ограничений внутренней реализации WebAssembly API переходов может гарантировать отражение изменений только в памяти плагина, но не в глобальных переменных WebAssembly. Если ваш плагин полагается на то, что изменения глобальных переменных будут видны после перехода, возможно, вам стоит пока избегать использования API переходов. Мы надеемся снять это ограничение в будущем.

```typst
#let base = plugin("hello-mut.wasm")
#assert.eq(base.get(), "[]")

#let mutated = plugin.transition(base.add, "hello")
#assert.eq(base.get(), "[]")
#assert.eq(mutated.get(), "[hello]")
```

```typst
plugin.transition(
  function,
  ..bytes,
) -> module
```

**Тип:** [function](/docs/typst/reference/foundations/function) · **Модификаторы:** Обязательный, Позиционный

Функция плагина для вызова.

#### `arguments` [#definitions-transition-arguments]

**Тип:** [bytes](/docs/typst/reference/foundations/bytes) · **Модификаторы:** Обязательный, Позиционный, Вариативный
