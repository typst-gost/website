Путь в файловой системе.

Когда вы разбиваете проект или пакет на несколько файлов или ссылаетесь на ресурсы, такие как изображения или библиографии, вам придётся работать с _путями._

## Строки путей [#path-strings]

Обычно пути просто выражаются как [строки](/docs/typst/reference/foundations/str). Встроенные функции, которые ожидают пути, как правило, также принимают строки. Например, вы можете написать:

```typst
#figure(
  // Path to an image
image("tiger.jpg"),
  caption: [A tiger],
)

// Path to a Typst file
#include "chapter.typ"
```

Существует два вида таких строк путей: относительные и абсолютные.

- **Относительный путь** разрешается относительно родительского каталога файла Typst, в котором вызывается функция. Хотя это поведение по умолчанию, путь также можно явно указать как относительный, начав его с `./`.
  ```typst
  #image("images/logo.png")
  #image("./images/logo.png") // This is equivalent
  ```
- **Абсолютный путь** всегда разрешается относительно [_корня_](#project-root) проекта. Такой путь обозначается ведущим `/`:
  ```typst
  #image("/assets/logo.png")
  ```

Пути состоят из сегментов, разделённых прямыми косыми чертами, при этом внутренние сегменты обозначают каталоги, а последний — файл или каталог. Есть два компонента пути, которые обрабатываются особым образом:

- Сегмент `.` относится к _текущему_ каталогу. Именно поэтому `"./image.png"` и `"image.png"` эквивалентны.
- Сегмент `..` относится к _родительскому_ каталогу. Если у вас есть три файла `main.typ`, `utils.typ` и `text/chapter1.typ`, то вы можете сослаться на ваш файл с утилитами из главы 1 через путь `"../utils.typ"`.

## Тип path [#path-type]

Для большинства типичных случаев использования путей вам достаточно строк. Однако иногда требуется немного больше контроля. Например, вы можете захотеть разрешить путь относительно файла, в котором вы сейчас пишете, а затем передать его пакету и позволить пакету читать из этого пути. Здесь и пригодится тип path.

С его помощью вы можете полностью разрешить строку пути относительно файла, в котором вы её создаёте. Любые последующие операции, выполняемые с этим путём (такие как чтение файла или загрузка изображения), будут вести себя одинаково независимо от того, где в коде они происходят.

Вот пример того, как у нас мог бы быть `main.typ` с файлом `data.json` прямо рядом с ним, и при этом мы могли бы позволить созданному нами пакету прочитать этот файл.

```typst
// This is main.typ, with data.json next to it.
#import "@local/my-pkg:0.1.0": process
#let data-path = path("data.json")
#process(data-path)
```

## Корни [#roots]

### Корень проекта [#project-root]

По соображениям безопасности и воспроизводимости Typst инкапсулирует доступ к файлам. Проект Typst может обращаться только к путям в пределах своего _корня проекта._ Если вы попытаетесь создать путь или обратиться к пути за пределами этого корня, вы получите ошибку:

```typst
// ❌ Error: path `"../secret.txt"` would escape the project root
#path("../secret.txt")
```

По умолчанию корнем проекта является родительский каталог главного файла Typst. Если вы хотите использовать другую папку в качестве корня вашего проекта, вы можете использовать флаг `--root` в CLI:

```bash
typst compile --root .. file.typ
```

Убедитесь, что главный файл находится в поддереве этой папки, чтобы Typst мог получить к нему доступ.

В веб-приложении сам проект является корневым каталогом. Вы всегда можете читать все файлы внутри него, независимо от того, какой из них просматривается (с помощью переключателя в виде глаза рядом с каждым файлом Typst на панели файлов).

### Корни пакетов [#package-roots]

Как и проект, каждый импортируемый вами пакет имеет свой собственный корень. Внутри пакета абсолютные пути указывают на корень пакета, а не на корень проекта. Сам по себе код в пакете не может создать путь, который находится в проекте или другом пакете.

Если вам нужно предоставить пакету ресурсы из проекта (например, изображение логотипа), вы можете сделать это, явно создав путь к ресурсу в вашем коде с помощью [конструктора path](#constructor). Затем вы можете передать полученный путь пакету. Пример этого показан в разделе [«Тип path»](#path-type) выше.

В качестве альтернативы вы можете выполнить операцию с путём в вашем коде и передать результат пакету. Это может быть, например, результат вызова [`read`](/docs/typst/reference/data-loading/read) или готовое изображение (например, в виде именованного параметра `logo: image("mylogo.svg")`). Обратите внимание, что если вы передаёте изображение пакету таким образом, вы всё ещё можете настроить внешний вид изображения с помощью правила set внутри пакета.

## Дальнейшие операции [#further-operations]

На данный момент назначение типа path ограничивается корректной обработкой и передачей путей между файлами в вашем проекте и пакетах. В будущем он может предоставить дополнительные возможности, такие как проверка существования файла или перечисление файлов в каталоге.

## Конструктор [#constructor]

Создаёт путь из строки.

```typst
// A relative path without a leading slash.
// May optionally start with `./`.
#path("relative/path/to/file.typ")
#path("./relative/path/to/file.typ")

// An absolute path with a leading slash.
#path("/absolute/path/to/file.typ")
```

```typst
path(str | path)
```

### `path` [#constructor-path]

**Тип:** [str](/docs/typst/reference/foundations/str) или [path](/docs/typst/reference/foundations/path) · **Модификаторы:** Required, Positional

Преобразует строку или путь в путь.

Если это [строка пути](#path-strings):

- Если путь абсолютный, он разрешается относительно корня проекта или пакета, в котором вызывается эта функция.
- Если путь относительный, он разрешается относительно файла, в котором вызывается эта функция.

Если это уже `path`, он возвращается без изменений.
