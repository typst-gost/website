Typst включает в себя мощный скриптовый язык. Вы можете автоматизировать свои документы и создавать более сложные стили с помощью кода. Ниже приведён обзор концепций скриптов.

## Выражения [#expressions]

В Typst разметка и код объединены в одно целое. Все элементы, кроме самых распространённых, создаются с помощью _функций._ Чтобы сделать это максимально удобным, Typst предоставляет компактный синтаксис для встраивания выражения кода в разметку: выражение вводится с помощью решётки (`#`), а обычный разбор разметки возобновляется после завершения выражения. Если символ должен продолжить выражение, но его следует интерпретировать как текст, выражение можно принудительно завершить точкой с запятой (`;`). Вы можете [экранировать литерал `#` или `;` с помощью обратной косой черты](/docs/typst/reference/syntax#escapes).

<TypstRender
  code={`
  #emph[Hello] \\
  #emoji.face \\
  #"hello".len()
`}
  image="/typst_docs_assets/images/T5Fdad4O-Uuq0iUCvSmixA.png"
  alt=""
  editable={true}
/>

В приведённом выше примере показаны некоторые из доступных выражений, включая [вызовы функций](/docs/typst/reference/foundations/function), [обращения к полям](#fields) и [вызовы методов](#methods). Другие виды выражений рассматриваются в оставшейся части этой главы. Некоторые виды выражений несовместимы с синтаксисом решётки (например, выражения с бинарными операторами). Чтобы встроить их в разметку, можно использовать круглые скобки, как в `#(1 + 2)`.

## Блоки [#blocks]

Чтобы структурировать код и встраивать в него разметку, Typst предоставляет два вида _блоков:_

- **Блок кода:** `{ let x = 1; x + 2 }`<br />При написании кода вы, вероятно, захотите разбить вычисления на несколько инструкций, создать промежуточные переменные и так далее. Блоки кода позволяют написать несколько выражений там, где ожидается одно. Отдельные выражения в блоке кода следует разделять переводами строк или точками с запятой. Выходные значения отдельных выражений в блоке кода объединяются, чтобы определить значение блока. Выражения без полезного вывода, например привязки `let`, дают `none`, который может быть объединён с любым значением без эффекта.
- **Блок содержимого:** `[*Hey* there!]`<br />С помощью блоков содержимого вы можете обрабатывать разметку/содержимое как программное значение, сохранять его в переменных и передавать в [функции](/docs/typst/reference/foundations/function). Блоки содержимого ограничены квадратными скобками и могут содержать произвольную разметку. Блок содержимого даёт значение типа [content](/docs/typst/reference/foundations/content). Произвольное число блоков содержимого может быть передано в функции как завершающие аргументы. То есть `list([A], [B])` эквивалентно `list[A][B]`.

Блоки содержимого и кода могут быть вложены произвольным образом. В примере ниже `[hello ]` объединяется с выводом `a + [ the ] + b`, давая `[hello from the *world*]`.

<TypstRender
  code={`
  #{
    let a = [from]
    let b = [*world*]
    [hello ]
    a + [ the ] + b
  }
`}
  image="/typst_docs_assets/images/z9XrZo7953lUD-LZ9Zw7aQ.png"
  alt=""
  editable={true}
/>

## Привязки и деструктуризация [#bindings]

Как уже было показано выше, переменные можно определять с помощью привязок `let`. Переменной присваивается значение выражения, следующего за знаком `=`. [Допустимое имя переменной](/docs/typst/reference/syntax#identifiers) может содержать `-`, но не может начинаться с `-`. Присваивание значения необязательно: если значение не присвоено, переменная будет инициализирована как `none`. Ключевое слово `let` также можно использовать для создания [пользовательской именованной функции](/docs/typst/reference/foundations/function#defining-functions). К переменным можно обращаться до конца содержащего блока (или до конца файла, если содержащего блока нет).

<TypstRender
  code={`
  #let name = "Typst"
  This is #name's documentation.
  It explains #name.

  #let my-add(x, y) = x + y
  Sum is #my-add(2, 3).
`}
  image="/typst_docs_assets/images/gPpa0H8yOhpaDxToyjZLwg.png"
  alt=""
  editable={true}
/>

Привязки let также можно использовать для деструктуризации [массивов](/docs/typst/reference/foundations/array) и [словарей](/docs/typst/reference/foundations/dictionary). В этом случае структура левой части присваивания должна повторять массив или словарь: привязки соответствуют по позиции для массивов и по имени ключа для словарей. Оператор `..` можно использовать один раз в шаблоне, чтобы собрать остаток элементов массива или словаря.

<TypstRender
  code={`
  #let (x, y) = (1, 2)
  The coordinates are #x, #y.

  #let (a, .., b) = (1, 2, 3, 4)
  The first element is #a.
  The last element is #b.

  #let books = (
    Shakespeare: "Hamlet",
    Homer: "The Odyssey",
    Austen: "Persuasion",
  )

  #let (Austen,) = books
  Austen wrote #Austen.

  #let (Homer: h) = books
  Homer wrote #h.

  #let (Homer, ..other) = books
  #for (author, title) in other [
    #author wrote #title.
  ]
`}
  image="/typst_docs_assets/images/rMVElkIayqhyQ2Qpsr91KQ.png"
  alt=""
  editable={true}
/>

Вы можете использовать подчёркивание, чтобы отбросить элементы в шаблоне деструктуризации:

<TypstRender
  code={`
  #let (_, y, _) = (1, 2, 3)
  The y coordinate is #y.
`}
  image="/typst_docs_assets/images/HXWXobK8-fPSrvaaleFVPg.png"
  alt=""
  editable={true}
/>

Деструктуризация также работает в списках аргументов функций …

<TypstRender
  code={`
  #let left = (2, 4, 5)
  #let right = (3, 2, 6)
  #left.zip(right).map(
    ((a,b)) => a + b
  )
`}
  image="/typst_docs_assets/images/z68n6DRLu3BVPtnGohDarg.png"
  alt=""
  editable={true}
/>

… и в левой части обычных присваиваний. Это может быть полезно, среди прочего, для обмена значений переменных.

<TypstRender
  code={`
  #{
    let a = 1
  let b = 2
    (a, b) = (b, a)
    [a = #a, b = #b]
  }
`}
  image="/typst_docs_assets/images/NR_-BwIlhR27A6B7ANTMVQ.png"

## Условные выражения [#conditionals]

С помощью условного выражения вы можете отображать или вычислять разные вещи в зависимости от того, выполнено ли некоторое условие. Typst поддерживает выражения `if`, `else if` и `else`. Когда условие вычисляется как `true`, условное выражение даёт значение, полученное из тела if. В противном случае оно даёт значение, полученное из тела else.

<TypstRender
  code={`
  #if 1 < 2 [
    This is shown
  ] else [
    This is not.
  ]
`}
  image="/typst_docs_assets/images/wlMrPxUOdaBHoDIoaL5ilw.png"
  alt=""
  editable={true}
/>

Каждая ветвь может иметь в качестве тела блок кода или содержимого.

- `if condition {..}`
- `if condition [..]`
- `if condition [..] else {..}`
- `if condition [..] else if condition {..} else [..]`

## Циклы [#loops]

С помощью циклов вы можете повторять содержимое или вычислять что-либо итеративно. Typst поддерживает два типа циклов: циклы `for` и `while`. Первые выполняют итерацию по указанной коллекции, а вторые — до тех пор, пока условие остаётся выполненным. Как и блоки, циклы _объединяют_ результаты каждой итерации в одно значение.

В примере ниже три предложения, созданные циклом for, объединяются в одно значение содержимого, а массивы длины 1 в цикле while объединяются в один больший массив.

<TypstRender
  code={`
  #for c in "ABC" [
    #c is a letter.
  ]

  #let n = 2
  #while n < 10 {
    n = (n * 2) - 1
    (n,)
  }
`}
  image="/typst_docs_assets/images/dVuBSF08E38XlxrFkgmQgA.png"
  alt=""
  editable={true}
/>

Циклы for могут выполнять итерацию по различным коллекциям:

- `for value in array {..}`<br />Выполняет итерацию по элементам [массива](/docs/typst/reference/foundations/array). Здесь также можно использовать синтаксис деструктуризации, описанный в разделе [Привязки let](#bindings).
- `for pair in dict {..}`<br />Выполняет итерацию по парам «ключ — значение» [словаря](/docs/typst/reference/foundations/dictionary). Пары также можно деструктурировать с помощью `for (key, value) in dict {..}`. Это эффективнее, чем `for pair in dict.pairs() {..}`, поскольку не создаёт временный массив всех пар «ключ — значение».
- `for letter in "abc" {..}`<br />Выполняет итерацию по символам [строки](/docs/typst/reference/foundations/str). Технически она выполняется по графемным кластерам строки. В большинстве случаев графемный кластер — это просто одна кодовая точка. Однако графемный кластер может содержать несколько кодовых точек, например эмодзи-флаг.
- `for byte in bytes("😀") {..}`<br />Выполняет итерацию по [байтам](/docs/typst/reference/foundations/bytes), которые можно преобразовать из [строки](/docs/typst/reference/foundations/str) или [прочитать](/docs/typst/reference/data-loading/read) из файла без кодировки. Каждое значение байта — это [целое число](/docs/typst/reference/foundations/int) от `0` до `255`.

Для управления выполнением цикла Typst предоставляет инструкции `break` и `continue`. Первая выполняет досрочный выход из цикла, а вторая переходит к следующей итерации цикла.

<TypstRender
  code={`
  #for letter in "abc nope" {
    if letter == " " {
      break
    }

    letter
  }
`}
  image="/typst_docs_assets/images/eOMVv6ujYQl3vSiE5sQAIQ.png"
  alt=""
  editable={true}
/>

Тело цикла может быть блоком кода или содержимого:

- `for .. in collection {..}`
- `for .. in collection [..]`
- `while condition {..}`
- `while condition [..]`

## Поля [#fields]

Вы можете использовать _точечную нотацию_ для доступа к полям значения. Для значений типа [`content`](/docs/typst/reference/foundations/content) вы также можете использовать функцию [`fields`](/docs/typst/reference/foundations/content#definitions-fields), чтобы перечислить поля.

Рассматриваемое значение может быть:

- [словарём](/docs/typst/reference/foundations/dictionary), содержащим указанный ключ,
- [символом](/docs/typst/reference/foundations/symbol), имеющим указанный модификатор,
- [модулем](/docs/typst/reference/foundations/module), содержащим указанное определение,
- [содержимым](/docs/typst/reference/foundations/content), состоящим из элемента, имеющего указанное поле. Доступные поля соответствуют аргументам [функции элемента](/docs/typst/reference/foundations/function#element-functions), которые были переданы при создании элемента.

<TypstRender
  code={`
  #let it = [= Heading]
  #it.body \\
  #it.depth \\
  #it.fields()

  #let dict = (greet: "Hello")
  #dict.greet \\
  #emoji.face
`}
  image="/typst_docs_assets/images/v8hp50O5mOOHAVq_Wk5agA.png"
  alt=""
  editable={true}
/>

## Методы [#methods]

_Вызов метода_ — это удобный способ вызвать функцию, привязанную к [типу](/docs/typst/reference/foundations/type) значения. Например, мы можем вызвать функцию [`str.len`](/docs/typst/reference/foundations/str#definitions-len) следующими двумя эквивалентными способами:

<TypstRender
  code={`
  #str.len("abc") is the same as
  #"abc".len()
`}
  image="/typst_docs_assets/images/ir3htbO7VdM79SV25WLxUg.png"
  alt=""
  editable={true}
/>

Структура вызова метода — `value.method(..args)`, а его эквивалентный полный вызов функции — `type(value).method(value, ..args)`. Документация каждого типа перечисляет его привязанные функции. В настоящее время вы не можете определять собственные методы.

<TypstRender
  code={`
  #let values = (1, 2, 3, 4)
  #values.pop() \\
  #values.len() \\

  #("a, b, c"
      .split(", ")
      .join[ --- ])

  #"abc".len() is the same as
  #str.len("abc")
`}
  image="/typst_docs_assets/images/oORqSsT5AZJdDrukU3HjDA.png"
  alt=""
  editable={true}
/>

Есть несколько специальных функций, которые изменяют значение, для которого они вызываются (например, [`array.push`](/docs/typst/reference/foundations/array#definitions-push)). Эти функции _должны_ вызываться в форме метода. В некоторых случаях, когда метод вызывается только ради его побочного эффекта, его возвращаемое значение следует игнорировать (и не включать в объединение). Канонический способ отбросить значение — привязка let: `let _ = array.remove(1)`.

## Модули [#modules]

Вы можете разделить свои проекты Typst на несколько файлов, называемых _модулями._ Модуль может ссылаться на содержимое и определения другого модуля несколькими способами:

- **Включение:** `include "bar.typ"`<br />Вычисляет файл по [пути](/docs/typst/reference/foundations/path) `bar.typ` и возвращает полученное [содержимое](/docs/typst/reference/foundations/content).
- **Импорт:** `import "bar.typ"`<br />Вычисляет файл по [пути](/docs/typst/reference/foundations/path) `bar.typ` и вставляет полученный [модуль](/docs/typst/reference/foundations/module) в текущую область видимости как `bar` (имя файла без расширения). Вы можете использовать ключевое слово `as`, чтобы переименовать импортированный модуль: `import "bar.typ" as baz`. Вы можете импортировать вложенные элементы с помощью точечной нотации: `import "bar.typ": baz.a`.
- **Импорт элементов:** `import "bar.typ": a, b`<br />Вычисляет файл по [пути](/docs/typst/reference/foundations/path) `bar.typ`, извлекает значения переменных `a` и `b` (которые должны быть определены в `bar.typ`, например с помощью привязок `let`) и определяет их в текущем файле. Замена `a, b` на `*` загружает все переменные, определённые в модуле. Вы можете использовать ключевое слово `as`, чтобы переименовать отдельные элементы: `import "bar.typ": a as one, b as two`

Вместо строки или [пути](/docs/typst/reference/foundations/path) вы также можете использовать [значение модуля](/docs/typst/reference/foundations/module), как показано в следующем примере:

<TypstRender
  code={`
  #import emoji: face
  #face.grin
`}
  image="/typst_docs_assets/images/P2pR9JPYRMtLWXPehGp1Eg.png"
  alt=""
  editable={true}
/>

## Пакеты [#packages]

Чтобы повторно использовать строительные блоки в разных проектах, вы также можете создавать и импортировать _пакеты_ Typst. Импорт пакета задаётся тройкой из пространства имён, имени и версии.

<TypstRender
  code={`
  #import "@preview/example:0.1.0": add
  #add(2, 7)
`}
  image="/typst_docs_assets/images/DMwbPu1PFmvcOjUvqSbE5A.png"
  alt=""
  editable={true}
/>

Пространство имён `preview` содержит пакеты, которыми делится сообщество. Все доступные пакеты сообщества можно найти на [Typst Universe](https://typst.app/universe).

Если вы используете Typst локально, вы также можете создавать собственные системно-локальные пакеты. Подробнее об этом см. в [репозитории пакетов](https://github.com/typst/packages).

## Операторы [#operators]

В следующей таблице перечислены все доступные унарные и бинарные операторы с их действием, арностью (унарный, бинарный) и уровнем приоритета (более высокий связывает сильнее). Некоторые операции, такие как [остаток от деления](/docs/typst/reference/foundations/calc#functions-rem-euclid), не имеют специального синтаксиса и могут быть выполнены с помощью функций из модуля [`calc`](/docs/typst/reference/foundations/calc).

| **Оператор** | **Действие** | **Арность** | **Приоритет** |
| --- | --- | --- | --- |
| `-` | Отрицание | Унарный | 7 |
| `+` | Без эффекта (существует для симметрии) | Унарный | 7 |
| `*` | Умножение | Бинарный | 6 |
| `/` | Деление | Бинарный | 6 |
| `+` | Сложение | Бинарный | 5 |
| `-` | Вычитание | Бинарный | 5 |
| `==` | Проверка равенства | Бинарный | 4 |
| `!=` | Проверка неравенства | Бинарный | 4 |
| `<` | Проверка «меньше» | Бинарный | 4 |
| `<=` | Проверка «меньше или равно» | Бинарный | 4 |
| `>` | Проверка «больше» | Бинарный | 4 |
| `>=` | Проверка «больше или равно» | Бинарный | 4 |
| `in` | Проверка принадлежности коллекции | Бинарный | 4 |
| `not in` | Проверка непринадлежности коллекции | Бинарный | 4 |
| `not` | Логическое «не» | Унарный | 3 |
| `and` | Логическое «и» с коротким замыканием | Бинарный | 3 |
| `or` | Логическое «или» с коротким замыканием | Бинарный | 2 |
| `=` | Присваивание | Бинарный | 1 |
| `+=` | Присваивание со сложением | Бинарный | 1 |
| `-=` | Присваивание с вычитанием | Бинарный | 1 |
| `*=` | Присваивание с умножением | Бинарный | 1 |
| `/=` | Присваивание с делением | Бинарный | 1 |
