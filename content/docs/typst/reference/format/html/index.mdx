*Элемент* · *Доступно с: 0.13.0* · *Функциональный флагТребуется функция `html`*

Формат экспорта HTML в Typst (экспериментальный).

<Callout>
Экспорт HTML в Typst в настоящее время активно разрабатывается. Функция всё ещё очень неполная и доступна только для экспериментов за функциональным флагом. Не используйте эту функцию в производственных сценариях. В CLI вы можете поэкспериментировать с экспортом HTML, передав

`--features html`

или установив переменную окружения

`TYPST_FEATURES`

в значение

`html`

. В веб-приложении вы также можете включить её как экспериментальную функцию. Посетите

[отслеживающую задачу](https://github.com/typst/typst/issues/5512)

чтобы следить за прогрессом экспорта HTML и узнать больше о запланированных функциях.
</Callout>

HTML-файлы описывают документ структурно. Цель экспорта HTML в Typst — зафиксировать структуру входного документа и создать семантически богатый HTML, сохраняющий эту структуру. Полученный HTML должен быть доступным, удобочитаемым и редактируемым вручную и сторонними инструментами.

Экспорт в PDF, PNG и SVG, напротив, создаёт _визуальные_ представления полностью свёрстанного документа. Это различие в назначении форматов означает, что Typst не может просто создать идеальный HTML для ваших существующих документов Typst. Он не всегда может знать, какое наилучшее семантическое HTML-представление вашего контента.

Вместо этого он даёт _вам_ полный контроль: вы можете проверить текущий формат экспорта с помощью функции [`target`](/docs/typst/reference/foundations/target) и, когда он установлен в HTML, генерировать [сырые HTML-элементы](/docs/typst/reference/format/html/elem). Основное предполагаемое использование этих элементов — в шаблонах и правилах show. Таким образом, содержимое документа может быть полностью независимым от цели экспорта, а контент можно совместно использовать между экспортом в PDF и HTML.

В формате экспорта `html` Typst выводит один HTML-файл. Вы также можете использовать Typst для создания веб-сайта, состоящего из нескольких HTML-документов и дополнительных ресурсов. Typst называет такую коллекцию _bundle_ и поддерживает этот сценарий с помощью специальной [цели `bundle`](/docs/typst/reference/format/bundle). Обратитесь к её документации, чтобы узнать больше. Обратите внимание, что как в цели `html`, так и в цели `bundle` Typst в настоящее время всегда создаёт автономный HTML-файл. Поддержка создания фрагментов, которые можно интегрировать в другие HTML-документы, запланирована на будущее.

В настоящее время Typst не выводит таблицы стилей CSS, сосредоточиваясь вместо этого на создании семантической разметки. Вы, конечно, можете написать свои собственные стили CSS и всё равно получить выгоду от совместного использования вашего _контента_ между PDF и HTML. В будущем мы планируем предоставить вам возможность автоматического вывода CSS с учётом большего числа ваших существующих правил set.

## Экспорт в HTML [#exporting-as-html]

### Командная строка [#command-line]

Передайте `--format html` в подкоманду `compile` или `watch` либо укажите имя выходного файла, оканчивающееся на `.html`. Обратите внимание, что вы также должны передать `--features html` или установить `TYPST_FEATURES=html`, чтобы включить эту экспериментальную цель экспорта.

При использовании `typst watch` Typst запустит HTTP-сервер с живой перезагрузкой. Вы можете настроить его следующим образом:

- Передайте `--port`, чтобы изменить порт. (По умолчанию используется первый свободный порт в диапазоне 3000–3005.)
- Передайте `--no-reload`, чтобы отключить внедрение скрипта живой перезагрузки. (На HTML, записываемый на диск, это никак не влияет.)
- Передайте `--no-serve`, чтобы полностью отключить сервер.

### Веб-приложение [#web-app]

Экспорт HTML можно включить как экспериментальную функцию в веб-приложении.

## Функциональность, специфичная для HTML [#html-specific-functionality]

Typst предоставляет функциональность, специфичную для HTML, в глобальном элементе `html`. Ниже приведены определения и параметры, которые он содержит.

## Параметры [#parameters]

```typst
html(pretty: bool) -> content
```

### `pretty` [#parameters-pretty]

**Тип:** [bool](/docs/typst/reference/foundations/bool) · **Модификаторы:** Settable · **По умолчанию:** `false`

Следует ли форматировать созданный HTML-документ с отступами.

Это форматирует вывод более удобочитаемым, но менее компактным по размеру способом.

## Определения [#definitions]

- [`elem`](/docs/typst/reference/format/html/elem)HTML-элемент, который может содержать контент Typst.
- [`frame`](/docs/typst/reference/format/html/frame)Элемент, который размещает своё содержимое как встроенный SVG.
- [typed](/docs/typst/reference/format/html/typed)Типизированный слой поверх сырых HTML-элементов.
