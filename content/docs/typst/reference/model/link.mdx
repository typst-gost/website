<span id="summary" />

*Элемент* · *Позиционируемый* · *Доступно: всегда*

Ссылка на URL или на местоположение в документе.

По умолчанию ссылки ничем не отличаются от обычного текста. Однако вы можете легко применить желаемый стиль с помощью правила show.

## Пример [#example]

<TypstRender
  code={`
  #show link: underline
  https://example.com \\
  #link("https://example.com") \\
  #link("https://example.com")[
    See example.com
  ]
`}

## Синтаксис [#syntax]

У этой функции также есть специальный синтаксис: текст, начинающийся с `http://` или `https://`, автоматически превращается в ссылку.

Чтобы избежать автоматического создания ссылки, вы можете поместить текст в [строку](/docs/typst/reference/foundations/str). Чтобы встроить строку в разметку, поставьте перед ней решётку. Кроме того, если похожий на ссылку текст является компьютерным кодом, вы также можете поместить его в [элемент `raw`](/docs/typst/reference/text/raw). Обратите внимание, что в обоих случаях текст может оставаться кликабельным в PDF, поскольку некоторые программы для чтения PDF автоматически распознают ссылки.

<TypstRender
  code={`
  #show link: set text(blue)

  // Automatic link
  https://example.com
  // String, not a link
  #"https://example.com"
  // Raw, not a link
  \`https://*.com\`
`}
  image="/typst_docs_assets/images/nqTURncRtOwr5_ywHdmvSg.png"
  alt=""
  editable={true}
/>

## Переносы [#hyphenation]

Если вы включите переносы или выравнивание по ширине, по умолчанию они не будут применяться к ссылкам, чтобы предотвратить нежелательные переносы в URL. Вы можете отказаться от этого поведения по умолчанию с помощью `show link: set text(hyphenate: true)`.

## Доступность [#accessibility]

Назначение ссылки должно быть понятно из самого текста ссылки или, по крайней мере, из непосредственно окружающего её текста. При экспорте в PDF Typst автоматически создаёт всплывающую подсказку для ссылок на основе их назначения. Для ссылок на URL в качестве подсказки будет использоваться сам URL.

## Ссылки при экспорте в HTML [#links-in-html-export]

При [экспорте в HTML](/docs/typst/reference/format/html) ссылка на [метку](/docs/typst/reference/foundations/label) или [местоположение](/docs/typst/reference/introspection/location) превращается во фрагментную ссылку на именованную точку привязки. Для поддержки этого цели без существующего ID автоматически получают ID в DOM. То, как это работает, зависит от того, в какой вид HTML-узла (или узлов) превратился целевой объект ссылки:

- Если целевой объект ссылки превратился в единственный HTML-элемент, этот элемент получит ID. Обычно так бывает, например, при ссылке на заголовок верхнего уровня (который превращается в единственный элемент `<h2>`).
- Если целевой объект ссылки превратился в единственный текстовый узел, этот узел будет обёрнут в `<span>`, который затем получит ID.
- Если целевой объект ссылки превратился в несколько узлов, ID получит первый узел.
- Если целевой объект ссылки не превратился ни в один узел, будет создан пустой span, который послужит целевым объектом ссылки.

Если вы полагаетесь на конкретную структуру DOM, вам следует убедиться, что целевой объект ссылки превращается в один или несколько элементов, поскольку компилятор не даёт гарантий относительно точного разбиения текста на текстовые узлы.

Если это возможно, автоматическая генерация ID пытается повторно использовать метку целевого объекта ссылки для создания удобочитаемого ID. Метку можно повторно использовать, если:

- Все символы являются буквенными или цифровыми согласно Unicode, либо дефисом, либо знаком подчёркивания.
- Метка не начинается с цифры или дефиса.

Эти правила гарантируют, что метка является одновременно допустимым идентификатором CSS и допустимым фрагментом URL для связывания.

Поскольку ID в DOM должны быть уникальными, при повторном использовании меток в качестве ID может потребоваться устранение неоднозначности. Точные правила таковы:

- Если метку можно повторно использовать и она уникальна в документе, она напрямую используется как ID.
- Если её можно повторно использовать, но она не уникальна, добавляется суффикс, состоящий из дефиса и целого числа. Например, если метка `<mylabel>` встречается дважды, она превратится в `mylabel-1` и `mylabel-2`.
- В противном случае генерируется уникальный ID вида `loc-`, за которым следует целое число.

## Ссылки при экспорте в пакет [#links-in-bundle-export]

При [экспорте в пакет](/docs/typst/reference/format/bundle) связывание по-прежнему работает как обычно. Например, если вы прикрепите метку к элементу в одном документе, ссылки в других документах смогут ссылаться на эту метку. Кроме того, документы и ресурсы также можно напрямую связывать. Чтобы сослаться на целый документ или ресурс, вы можете прикрепить к нему метку или выполнить [запрос](/docs/typst/reference/introspection/query) к нему и извлечь его [местоположение](/docs/typst/reference/introspection/location).

```typst
#document("index.html")[
  // Link to document.
#link(<appendix>)[To appendix]

  // Link into document.
  See the #link(<glossary>)[Glossary]
  for more information.
]

#document("appendix.html")[
  = Definitions
...
= Glossary <glossary>
...
] <appendix>
```

Междокументные ссылки выводятся как относительные пути (возможно, с фрагментами). Typst автоматически назначает имена привязок для каждого документа на основе тех же правил, что и при экспорте в HTML. В документах HTML и SVG они выводятся как атрибуты `id` на элементах. В документах PDF они выводятся как _именованные назначения._ Документы PNG не поддерживают связывание.

Обратите внимание, что ссылки всегда используют полные относительные пути. В некоторых сценариях (прежде всего для многостраничных веб-сайтов) это может быть нежелательно. Например, вы можете захотеть сгенерировать документ `/blog/index.html`, но при этом ссылаться на него просто как на `/blog`. Кроме того, ваш веб-сервер может считать `/blog` и `/blog/` взаимозаменяемыми и отдавать `/blog/index.html` для обоих. Если затем пользователь перейдёт на `/blog`, относительные ссылки на другие страницы, сгенерированные Typst, перестанут работать. В настоящее время у Typst нет способа напрямую подключиться к встроенной обработке ссылок. Тем не менее, при экспорте в HTML, в зависимости от вашего случая использования, можно скорректировать встроенную обработку ссылок с помощью правила show на `html.elem.where(tag: "a")`.

## Параметры [#parameters]

```typst
link(
  str | label | location | dictionary,
  content,
)
```

### `dest` [#parameters-dest]

**Тип:** [str](/docs/typst/reference/foundations/str) или [label](/docs/typst/reference/foundations/label) или [location](/docs/typst/reference/introspection/location) или [dictionary](/docs/typst/reference/foundations/dictionary) · **Модификаторы:** Обязательный, Позиционный

Назначение, на которое указывает ссылка.

- Чтобы сослаться на веб-страницы, `dest` должен быть допустимой строкой URL. Если URL использует схему `mailto:` или `tel:` и параметр `body` опущен, адрес электронной почты или номер телефона станет телом ссылки без схемы.
- Чтобы сослаться на другую часть документа, `dest` может принимать одну из трёх форм:
  - [Метка](/docs/typst/reference/foundations/label), прикреплённая к элементу. Если вы также хотите получить автоматический текст для ссылки на основе элемента, рассмотрите возможность использования [перекрёстной ссылки](/docs/typst/reference/model/ref) вместо этого.
  - [`location`](/docs/typst/reference/introspection/location) (обычно полученное из [`here`](/docs/typst/reference/introspection/here), [`locate`](/docs/typst/reference/introspection/locate) или [`query`](/docs/typst/reference/introspection/query)).
  - Словарь с ключом `page` типа [integer](/docs/typst/reference/foundations/int) и координатами `x` и `y` типа [length](/docs/typst/reference/layout/length). Страницы считаются с единицы, а координаты отсчитываются от верхнего левого угла страницы.

### `body` [#parameters-body]

**Тип:** [content](/docs/typst/reference/foundations/content) · **Модификаторы:** Обязательный, Позиционный

Содержимое, которое должно стать ссылкой.

Если `dest` является строкой URL, параметр можно опустить. В этом случае URL будет показан как ссылка.
