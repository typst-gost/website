<span id="summary" />

*Элемент* · *Позиционируемый* · *Доступно с: всегда*

Неформатированный текст с необязательной подсветкой синтаксиса.

Отображает текст дословно и моноширинным шрифтом. Обычно используется для встраивания компьютерного кода в документ.

Текст, переданный этому элементу, игнорирует синтаксис разметки, такой как `*strong*` или `_emphasis_`, и отображается дословно. Если вы хотите отобразить содержимое моноширинным шрифтом, сохранив при этом возможность использования синтаксиса разметки, вместо [`raw`](/docs/typst/reference/text/raw) можно явно задать моноширинный шрифт для текста с помощью параметра [`text.font`](/docs/typst/reference/text/text#parameters-font).

Элементы raw в основном создаются с помощью их [специального синтаксиса](#syntax) путём заключения текста в один или три и более символов обратной кавычки (`` ` ``) с обеих сторон. При использовании трёх и более обратных кавычек текст, непосредственно следующий за начальными обратными кавычками, рассматривается как [языковой тег](#parameters-lang), используемый для подсветки синтаксиса, а сам неформатированный текст начинается после первого пробельного символа.

## Стилизация [#styling]

По умолчанию элемент `raw` использует шрифт `DejaVu Sans Mono` (входящий в состав Typst) с уменьшенным размером шрифта `0.8em` (то есть 80% от глобального размера шрифта). Это связано с тем, что моноширинные шрифты, как правило, визуально крупнее немоноширинных.

Вы можете настроить эти свойства с помощью правил show-set:

<TypstRender
  code={`
  // Switch to Cascadia Code for both
  // inline and block raw.
  #show raw: set text(font: "Cascadia Code")

  // Reset raw blocks to the same size as normal text,
  // but keep inline raw at the reduced size.
  #show raw.where(block: true): set text(1em / 0.8)

  Now using the \`Cascadia Code\` font for raw text.
  Here's some Python code. It looks larger now:

  \`\`\`py
  def python():
    return 5 + 5
  \`\`\`
`}
  image="/typst_docs_assets/images/p48sRQvzVxCEAwAeSEdmUA.png"
  alt=""
  editable={true}
/>

Кроме того, вы можете настроить цвета подсветки синтаксиса, задав пользовательскую тему через параметр [`theme`](#parameters-theme).

Для полной настройки внешнего вида блока raw может оказаться полезным правило show для [`raw.line`](#definitions-line), например, для добавления номеров строк.

Обратите внимание, что в неформатированном тексте такие функции вёрстки, как [перенос слов](/docs/typst/reference/text/text#parameters-hyphenate), [свисание знаков](/docs/typst/reference/text/text#parameters-overhang), [интервалы между CJK и латиницей](/docs/typst/reference/text/text#parameters-cjk-latin-spacing) и (для блоков raw) [выравнивание по ширине](/docs/typst/reference/model/par#parameters-justify), по умолчанию отключены.

## Синтаксис [#syntax]

Эта функция имеет специальный синтаксис, который создаёт элемент raw как в режиме разметки, так и в режиме кода. Вы можете заключить текст в один или три и более символов обратной кавычки (`` ` ``) с обеих сторон, чтобы сделать его неформатированным. Количество обратных кавычек должно быть одинаковым с обеих сторон, а заключённый текст не может содержать группу из такого же количества обратных кавычек подряд. Запись всего двух обратных кавычек (``` `` ```) создаёт пустой неформатированный текст.

К заметным отличиям от Markdown относится то, что одиночные обратные кавычки могут заключать текст, занимающий несколько строк, без удаления отступов, а синтаксис с тремя и более обратными кавычками по-прежнему интерпретирует языковые теги при использовании в строке.

Неформатированный текст, заключённый в _одиночные_ обратные кавычки, не имеет способа указать языковой тег и всегда рассматривается как строчный для использования внутри абзаца, то есть параметр [`block`](#parameters-block) равен `false`.

Синтаксис raw с использованием _трёх и более_ обратных кавычек обладает следующими свойствами:

- **После начальных обратных кавычек блок raw завершается только последовательностью из такого же количества обратных кавычек**

  Чтобы включить текст, содержащий последовательность обратных кавычек, начальные и конечные обратные кавычки должны содержать как минимум на одну обратную кавычку больше, чем эта последовательность.
- **Если неформатированный текст содержит разрыв строки, он будет блочным, иначе — строчным**

  Это соответственно устанавливает параметр [`block`](#parameters-block) в `true` или `false`.
- **Текст, непосредственно следующий за начальными обратными кавычками, вплоть до первого пробельного символа, рассматривается как _языковой тег_, используемый для подсветки синтаксиса**

  Конкретные правила относительно того, какой текст может рассматриваться как языковой тег, планируется изменить, и они [подробно объяснены ниже.](#language-tag-changes)
- **Начальная и конечная строки имеют особое поведение при обрезке**

  Для начальной строки, если все символы после начальных обратных кавычек или языкового тега являются пробельными, вся строка будет обрезана. Однако если в этой строке есть непробельные символы, будет обрезан только один пробел, непосредственно следующий за начальными обратными кавычками или языковым тегом, если он присутствует.

  Если конечная строка состоит целиком из пробельных символов вплоть до закрывающих обратных кавычек, она будет обрезана. В противном случае, если последний непробельный символ конечной строки является обратной кавычкой, то один пробельный символ будет обрезан с конца строки, если он присутствует.
- **Общий отступ в начале строк обрезается**

  Typst удалит начальные пробельные символы в начале строк неформатированного текста, которые являются общими для всех строк, то есть общий отступ. При этом текст в строке с начальными обратными кавычками исключается.

  Сначала Typst находит строку с наименьшим количеством начальных пробельных символов, содержащую какие-либо непробельные символы, включая строку с закрывающими обратными кавычками. Затем Typst обрезает в каждой строке количество символов, равное количеству начальных пробельных символов в этой строке. В строках, состоящих только из пробельных символов, будет удалено такое же количество символов до тех пор, пока они не станут пустыми, но любые дополнительные конечные пробельные символы сохранятся.

  Обратите внимание, что эта проверка для простоты рассматривает табуляции и пробелы как эквивалентные символы и работает с количеством [кодовых точек Unicode](https://www.unicode.org/glossary/#code_point), то есть символов, а не с длиной в байтах.

Эти свойства синтаксиса с тремя и более обратными кавычками позволяют использовать некоторые неочевидные сценарии:

- Чтобы написать текст, содержащий последовательность обратных кавычек, заключите его в на одну или более обратных кавычек больше, чем эта последовательность: ````` ```` enclosed```backticks```` `````
- Чтобы написать текст, начинающийся или заканчивающийся обратной кавычкой, добавьте пробел внутри открывающих и закрывающих обратных кавычек: ```` ``` `backticks` ``` ````
- Чтобы написать строчный текст с подсветкой по языковому тегу, добавьте пробел между языковым тегом и текстом ```` ```rust fn main() {}```{:rust} ````
- Чтобы написать строчный текст без какого-либо языкового тега, добавьте пробел после начальных обратных кавычек: ```` ``` text``` ```` или используйте синтаксис с одиночными обратными кавычками: `` `text` ``

### Встраивание строк с помощью синтаксиса raw [#embedding-strings]

Распространённый сценарий использования синтаксиса raw — встраивание данных в виде строк с форматированием путём доступа к полю `.text` неформатированного содержимого для получения лежащей в основе строки. Это также можно сочетать с конструктором [`bytes`](/docs/typst/reference/foundations/bytes) для преобразования строки в байты.

### Изменения языковых тегов [#language-tag-changes]

При использовании синтаксиса raw с тремя и более обратными кавычками текст, непосредственно следующий за начальными обратными кавычками (вплоть до первого пробельного символа), рассматривается как [языковой тег](#parameters-lang). Однако в текущей версии Typst только текст, который был бы допустимым идентификатором Typst, рассматривается как языковой тег. Первый символ, недопустимый для идентификатора, будет интерпретироваться как начало неформатированного текста.

Например, в текущей версии Typst, если блок raw начинается с `C++`, идентификатор `C` будет языковым тегом, а неформатированный текст начнётся с `++`. Если блок raw начинается с `++C`, у него не будет языкового тега, а неформатированный текст начнётся с `++C`.

Чтобы использовать языковые теги, недопустимые в качестве идентификаторов в текущей версии Typst, необходимо использовать параметр [`lang`](#parameters-lang), либо вызвав конструктор со строкой: `#raw("text", lang: "...")`, либо написав правило set: `#set raw(lang: "...")`.

В следующей версии Typst _весь текст_ вплоть до первого пробельного символа или обратной кавычки будет рассматриваться как языковой тег, что позволит использовать более широкий набор символов для языковых тегов. Теги, содержащие пробелы или обратные кавычки, по-прежнему потребуется задавать вручную через параметр [`lang`](#parameters-lang).

Typst предупредит вас, если ваши блоки raw будут интерпретироваться иначе в следующей версии Typst, выдав предупреждение.

```typst
raw(
  str,
```

### `block` [#parameters-block]

**Тип:** [bool](/docs/typst/reference/foundations/bool) · **Модификаторы:** Устанавливаемый · **По умолчанию:** `false`

Отображается ли неформатированный текст как отдельный блок.

В режиме разметки использование записи с одной обратной кавычкой делает этот параметр равным `false`. Использование записи с тремя обратными кавычками делает его равным `true`, если заключённое содержимое содержит хотя бы один разрыв строки.

### `lang` [#parameters-lang]

**Тип:** [none](/docs/typst/reference/foundations/none) или [str](/docs/typst/reference/foundations/str) · **Модификаторы:** Устанавливаемый · **По умолчанию:** `none`

Язык, как который следует интерпретировать неформатированный текст для подсветки синтаксиса.

При [экспорте в HTML](/docs/typst/reference/format/html) это устанавливает атрибут `data-lang` у сгенерированного элемента [`html.code`](/docs/typst/reference/format/html/typed#functions-code).

### `align` [#parameters-align]

**Тип:** [alignment](/docs/typst/reference/layout/alignment) · **Модификаторы:** Устанавливаемый · **По умолчанию:** `start`

Горизонтальное выравнивание, которое должна иметь каждая строка в блоке raw. Этот параметр игнорируется, если это не блок raw (если указано `block: false` или в режиме разметки использовались одиночные обратные кавычки).

По умолчанию он установлен в `start`, что означает, что неформатированный текст по умолчанию выравнивается по началу направления текста внутри блока, независимо от выравнивания текущего контекста (что позволяет вам, например, центрировать сам блок raw, не центрируя текст внутри него).

  let f(x) = x
  code = "centered"
  \`\`\`
`}

### `syntaxes` [#parameters-syntaxes]

**Тип:** [str](/docs/typst/reference/foundations/str) или [path](/docs/typst/reference/foundations/path) или [bytes](/docs/typst/reference/foundations/bytes) или [array](/docs/typst/reference/foundations/array) · **Модификаторы:** Устанавливаемый · **По умолчанию:** `()`

Дополнительные определения синтаксиса для загрузки. Определения синтаксиса должны быть в [формате файла `sublime-syntax`](https://www.sublimetext.com/docs/syntax.html).

Вы можете передать любое из следующих значений:

- Строку пути или [`path`](/docs/typst/reference/foundations/path) для загрузки файла синтаксиса.
- Необработанные байты, из которых следует декодировать синтаксис.
- Массив, каждый элемент которого является одним из вышеперечисленного.

Список встроенных синтаксисов см. в документации [параметра `lang`](#parameters-lang).

### `theme` [#parameters-theme]

**Тип:** [none](/docs/typst/reference/foundations/none) или [auto](/docs/typst/reference/foundations/auto) или [str](/docs/typst/reference/foundations/str) или [path](/docs/typst/reference/foundations/path) или [bytes](/docs/typst/reference/foundations/bytes) · **Модификаторы:** Устанавливаемый · **По умолчанию:** `auto`

Тема, используемая для подсветки синтаксиса. Темы должны быть в [формате файла `tmTheme`](https://www.sublimetext.com/docs/color_schemes_tmtheme.html).

Вы можете передать любое из следующих значений:

- `none`: Отключает подсветку синтаксиса.
- `auto`: Подсветка с использованием темы Typst по умолчанию.
- Строку пути или [`path`](/docs/typst/reference/foundations/path) для загрузки файла темы.
- Необработанные байты, из которых следует декодировать тему.

Применение темы влияет только на цвет специально подсвеченного текста. Оно не учитывает свойства переднего плана и фона темы, так что вы сохраняете контроль над цветом неформатированного текста. Вы можете применить цвет переднего плана самостоятельно с помощью функции [`text`](/docs/typst/reference/text/text), а фон — с помощью [заполненного блока](/docs/typst/reference/layout/block#parameters-fill). Вы также можете использовать функцию [`xml`](/docs/typst/reference/data-loading/xml) для извлечения этих свойств из темы.

  )

## Функции [#functions]

### `line` [#definitions-line]

*Элемент* · *Доступно с: 0.9.0*

Подсвеченная строка неформатированного текста.

Это вспомогательный элемент, который синтезируется элементами [`raw`](/docs/typst/reference/text/raw).

Он позволяет вам получать доступ к различным свойствам строки, таким как номер строки, неформатированный неподсвеченный текст, подсвеченный текст и является ли она первой или последней строкой блока raw.

```typst
raw.line(
  int,
  int,
  str,
  content,
)
```

#### `number` [#definitions-line-number]

**Тип:** [int](/docs/typst/reference/foundations/int) · **Модификаторы:** Обязательный, Позиционный

Номер строки raw внутри блока raw, начинается с 1.

#### `count` [#definitions-line-count]

**Тип:** [int](/docs/typst/reference/foundations/int) · **Модификаторы:** Обязательный, Позиционный

Общее количество строк в блоке raw.

#### `text` [#definitions-line-text]

**Тип:** [str](/docs/typst/reference/foundations/str) · **Модификаторы:** Обязательный, Позиционный

Строка неформатированного текста.

#### `body` [#definitions-line-body]

**Тип:** [content](/docs/typst/reference/foundations/content) · **Модификаторы:** Обязательный, Позиционный

Подсвеченный неформатированный текст.
