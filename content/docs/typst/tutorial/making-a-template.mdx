В предыдущих трёх главах этого учебного пособия вы узнали, как написать документ в Typst, применить базовые стили и глубоко настроить его внешний вид в соответствии с руководством по стилю издателя. Поскольку статья, которую вы написали в предыдущей главе, имела огромный успех, вас попросили написать продолжение для той же конференции. На этот раз вы хотите взять стиль, созданный в предыдущей главе, и превратить его в переиспользуемый шаблон. В этой главе вы узнаете, как создать шаблон, который вы и ваша команда сможете использовать с помощью всего одного правила show. Давайте начнём!

## Переиспользование данных с помощью переменных [#variables]

В прошлых главах большая часть содержимого документа вводилась вручную. В третьей главе мы использовали элемент `document` и контекст, чтобы сократить повторения и ввести заголовок только один раз. Но на практике в вашем документе может быть гораздо больше вещей, которые встречаются несколько раз. Есть несколько веских причин определить такие повторяющиеся значения всего один раз:

1. Это упрощает их изменение в дальнейшем
2. Это позволяет быстро найти все места, где вы что-то использовали
3. Это помогает легко сохранять единообразие по всему документу
4. Для длинных или сложных для ввода повторяющихся фрагментов более короткое имя переменной часто удобнее набирать

Если бы вы использовали обычный текстовый процессор, вы могли бы прибегнуть к использованию текста-заполнителя, который позже можно найти поиском. В Typst же вы можете вместо этого использовать переменные, чтобы безопасно хранить содержимое и переиспользовать его по всему документу через имя переменной.

Техника использования контекста для воспроизведения свойства элемента, которую мы изучили ранее, не всегда наиболее уместна для этого: встроенные элементы Typst ориентированы на семантические свойства, такие как заголовок и описание документа, или на вещи, непосредственно связанные с вёрсткой, например размер текста.

В нашем примере мы хотим рассмотреть произношение слова Typst. Один из лучших способов транскрибировать произношение — Международный фонетический алфавит (МФА). Но поскольку в нём используются символы, которых нет на обычных клавиатурах, повторный ввод МФА может стать обременительным. Поэтому давайте вместо этого определим переменную, к которой мы сможем обращаться несколько раз.

```typst
#let ipa = [taɪpst]
```

Здесь мы используем новое ключевое слово `let`, чтобы обозначить определение переменной. Затем мы указываем имя нашей переменной, в данном случае `ipa`. Наконец, мы ставим знак равенства и значение нашей переменной. Оно заключено в квадратные скобки, потому что это содержимое, что повторяет то, как вы вызвали бы функцию, принимающую содержимое. Иными словами, этот синтаксис отражает фразу _«Пусть переменная `ipa` имеет значение `[taɪpst]`.»_

Теперь мы можем использовать переменную в нашем документе:

<TypstRender
  code={`
  #let ipa = [taɪpst]

  The canonical way to
  pronounce Typst is #ipa.

  #table(
    columns: (1fr, 1fr),
    [Name], [Typst],
    [Pronunciation], ipa,
  )
`}
  image="/typst_docs_assets/images/RF0LhFCSYBnrIgM61y71Ew.png"
  alt=""
  editable={true}
/>

В примере видно, что переменную можно использовать как в разметке (с префиксом `#`), так и в вызове функции (просто набрав её имя). Разумеется, мы можем изменить значение переменной, и все её вхождения автоматически изменятся вместе с ним. Давайте немного яснее покажем, что является МФА, а что — обычной прозой, отобразив МФА курсивом. Мы также используем косые черты, которые по соглашению часто окружают МФА.

<TypstRender
  code={`
  #let ipa = text(
    style: "italic",
  )[/taɪpst/]

  The canonical way to
  pronounce Typst is #ipa.

  #table(
    columns: (1fr, 1fr),
    [Name], [Typst],
    [Pronunciation], ipa,
  )
`}
  image="/typst_docs_assets/images/82h59PM6M_3aCX1m9j1ZvA.png"
  alt=""
  editable={true}
/>

Здесь мы вызвали функцию text и присвоили её _возвращаемое значение_ переменной. Когда вы вызываете функцию, она обрабатывает свои аргументы и затем возвращает другое значение (часто содержимое). До сих пор в этом учебном пособии мы вызывали большинство функций непосредственно в разметке, вот так: `#text(fill: red)[CRIMSON!]`. Этот вызов функции text возвращает красный текст в качестве возвращаемого значения. Поскольку мы разместили его в разметке, его возвращаемое значение сразу же вставилось в написанное нами содержимое. С переменными мы можем вместо этого сохранить его, чтобы использовать позже или скомпоновать с другими значениями.

Переменные не ограничены хранением содержимого: они могут хранить любой тип данных, известный Typst. На протяжении этого учебного пособия вы использовали множество типов данных, передавая их встроенным функциям Typst. Вот пример присваивания каждого из них переменной:

```typst
// Content with markup inside
#let blind-text = [_Lorem ipsum_ dolor sit amet]

// Unformatted strings
#let funny-font = "MS Comic Sans"
// Absolute lengths (see also pt, in, ...)
#let mile = 160934cm
// Lengths relative to the font size
#let double-space = 2em
// Ratios
#let progress = 80%
// Integer numbers
#let answer = 42
// Booleans
#let truth = false
// Horizontal and vertical alignment
#let focus = center
```

В этой главе учебного пособия вы будете использовать переменные и собственные функции для создания шаблонов, которые можно переиспользовать в нескольких документах.

## Игрушечный шаблон [#toy-template]

В Typst шаблоны — это функции, в которые вы можете обернуть весь свой документ. Чтобы узнать, как это сделать, давайте сначала вспомним, как писать собственные функции. Они могут делать всё, что вы захотите, так почему бы не немного сойти с ума?

<TypstRender
  code={`
  #let amazed(term) = box[✨ #term ✨]

  You are #amazed[beautiful]!
`}
  image="/typst_docs_assets/images/gY65rAOjmKrYN8u8n0enxg.png"
  alt=""
  editable={true}
/>

Сравнивая это с предыдущим разделом, вы могли заметить, что это очень похоже на определение переменной с помощью `let`. Этот инстинкт верен: функции — это просто ещё один тип данных. Здесь мы определяем переменную `amazed`, присваивая ей функцию, которая принимает один аргумент, `term`, и возвращает содержимое с `term`, окружённым блёстками. Мы также поместили всё это в [`box`](/docs/typst/reference/layout/box), чтобы термин, которому мы удивляемся, нельзя было отделить от его блёсток переносом строки. Специальный синтаксис определения функции делает определение короче и читабельнее, но вы также можете использовать обычный синтаксис определения переменной (подробности см. в [справочнике по скриптам](/docs/typst/reference/scripting#bindings)). После её определения мы можем вызывать функцию так же, как и все встроенные функции.

Многие функции, поставляемые с Typst, имеют необязательные именованные параметры. Наши функции также могут их иметь. Давайте добавим в нашу функцию параметр, который позволит нам выбирать цвет текста. Нам нужно указать цвет по умолчанию на случай, если параметр не задан.

<TypstRender
  code={`
  #let amazed(term, color: blue) = {
    text(color, box[✨ #term ✨])
  }

  You are #amazed[beautiful]!
  I am #amazed(color: purple)[amazed]!
`}
  image="/typst_docs_assets/images/YaSVN7G1UkakrR9LizZPMg.png"
  alt=""
  editable={true}
/>

Теперь шаблоны работают путём оборачивания всего нашего документа в пользовательскую функцию, такую как `amazed`. Но оборачивать весь документ в гигантский вызов функции было бы обременительно! Вместо этого мы можем использовать правило show «для всего», чтобы достичь того же с более чистым кодом. Чтобы написать такое правило show, поставьте двоеточие сразу после ключевого слова show и затем укажите функцию. Этой функции передаётся остаток документа в качестве параметра. Затем функция может делать с этим содержимым всё что угодно. Поскольку функцию `amazed` можно вызвать с одним аргументом-содержимым, мы можем просто передать её по имени в правило show. Давайте попробуем:

<TypstRender
  code={`
  #show: amazed
  I choose to focus on the good
  in my life and let go of any
  negative thoughts or beliefs.
  In fact, I am amazing!
`}
  image="/typst_docs_assets/images/2UUifKUujuG_0aO9_2YlsA.png"
  alt=""
  editable={true}
/>

Теперь весь наш документ будет передан функции `amazed`, как если бы мы обернули его вокруг неё. Разумеется, это не особенно полезно с этой конкретной функцией, но в сочетании с правилами set и именованными аргументами это может быть очень мощным.

## Встраивание правил set и show [#set-and-show-rules]

Чтобы применить некоторые правила set и show к нашему шаблону, мы можем использовать `set` и `show` внутри блока содержимого в нашей функции, а затем вставить документ в этот блок содержимого.

<TypstRender
  code={`
  #let template(doc) = [
    #set text(font: "Inria Serif")
    #show "something cool": [Typst]
    #doc
  ]

  #show: template
  I am learning something cool today.
  It's going great so far!
`}
  image="/typst_docs_assets/images/AB1vsF8DXL9jEhbZ7F1baw.png"
  alt=""
  editable={true}
/>

Как мы уже выяснили в предыдущей главе, правила set применяются ко всему внутри их блока содержимого. Поскольку правило show «для всего» передаёт весь наш документ функции `template`, правило set для текста и правило show для строки в нашем шаблоне будут применяться ко всему документу. Давайте используем эти знания, чтобы создать шаблон, воспроизводящий стиль основного текста статьи, которую мы написали в предыдущей главе.

<TypstRender
  code={`
  #let conf(title, doc) = {
    set page(
      paper: "us-letter",
      header: align(
        right + horizon,
        title
      ),
      columns: 2,
      ...
    )
    set par(justify: true)
    set text(
      font: "Libertinus Serif",
      size: 11pt,
    )

    // Heading show rules.
    ...

    doc
  }

  #show: doc => conf(
    [Paper title],
    doc,
  )

  = Introduction
  ...
`}
  image="/typst_docs_assets/images/sWBh-xz0p4CVSFtrM0Q4YA.png"
  alt=""
  editable={true}
/>

Большую часть этого кода мы скопировали из предыдущей главы. Отличий два:

1. Мы обернули всё в функцию `conf` с помощью правила show «для всего». Функция применяет несколько правил set и show и в конце выводит переданное ей содержимое.
2. Кроме того, мы использовали блок кода в фигурных скобках вместо блока содержимого. Так нам не нужно ставить префикс `#` перед всеми правилами set и вызовами функций. Взамен мы больше не можем писать разметку непосредственно в блоке кода.

Также обратите внимание, откуда берётся заголовок: ранее он находился внутри переменной. Теперь мы получаем его как первый параметр функции шаблона. Для этого мы передали замыкание (это функция без имени, которая используется сразу же) в правило show «для всего». Мы сделали это потому, что функция `conf` ожидает два позиционных аргумента — заголовок и тело, — но правило show передаст только тело. Поэтому мы добавляем новое определение функции, которое позволяет нам задать заголовок статьи и использовать единственный параметр из правила show.

## Шаблоны с именованными аргументами [#named-arguments]

Наша статья в предыдущей главе имела заголовок и список авторов. Мы можем оставить заголовок в качестве метаданных [`document`](/docs/typst/reference/model/document), но наш шаблон также должен принимать список авторов с их аффилиациями и аннотацию статьи. Мы добавим их как именованные аргументы. В итоге мы хотим, чтобы это работало так:

```typst
#set document(title: [
  A Fluid Dynamic Model for
  Glacier Flow
])

#show: doc => conf(
  authors: (
    (
      name: "Theresa Tungsten",
      affiliation: "Artos Institute",
      email: "tung@artos.edu",
    ),
    (
      name: "Eugene Deklan",
      affiliation: "Honduras State",
      email: "e.deklan@hstate.hn",
    ),
  ),
  abstract: lorem(80),
  doc,
)

...
```

Давайте создадим эту новую функцию шаблона. Заголовок можно отобразить с помощью функции [`title`](/docs/typst/reference/model/title) и получить через `document.title`, поэтому шаблону нужны только именованные параметры `authors` и `abstract` с пустыми значениями по умолчанию. Далее мы копируем код, который генерирует заголовок, аннотацию и авторов из предыдущей главы, в шаблон, заменяя фиксированные детали параметрами.

Новый параметр `authors` ожидает [массив](/docs/typst/reference/foundations/array) [словарей](/docs/typst/reference/foundations/dictionary) с ключами `name`, `affiliation` и `email`. Поскольку авторов может быть произвольное число, мы динамически определяем, нужны ли нам одна, две или три колонки для списка авторов. Сначала мы определяем количество авторов с помощью метода [`.len()`](/docs/typst/reference/foundations/array#definitions-len) на массиве `authors`. Затем мы задаём число колонок как минимум из этого количества и трёх, чтобы никогда не создавать больше трёх колонок. Если авторов больше трёх, вместо этого будет вставлена новая строка. Для этой цели мы также добавили параметр `row-gutter` в функцию `grid`. Иначе строки были бы слишком близко друг к другу. Чтобы извлечь сведения об авторах из словаря, мы используем [синтаксис доступа к полям](/docs/typst/reference/scripting#fields).

Нам всё ещё нужно предоставить аргумент для grid для каждого автора: здесь пригодится метод [`map`](/docs/typst/reference/foundations/array#definitions-map) массива. Он принимает функцию в качестве аргумента, которая вызывается для каждого элемента массива. Мы передаём ему функцию, которая форматирует сведения для каждого автора и возвращает новый массив, содержащий значения содержимого. Теперь у нас есть один массив значений, который мы хотели бы использовать как несколько аргументов для grid. Мы можем сделать это с помощью [оператора `spread`](/docs/typst/reference/foundations/arguments). Он принимает массив и применяет каждый его элемент как отдельный аргумент к функции.

Полученная функция шаблона выглядит так:

```typst
#let conf(
  authors: (),
  abstract: [],
  doc,
) = {
  // Set and show rules from before.
// ...
place(
    top + center,
    float: true,
    scope: "parent",
    clearance: 2em,
    {
      title()

      let count = authors.len()
      let ncols = calc.min(count, 3)
      grid(
        columns: (1fr,) * ncols,
        row-gutter: 24pt,
        ..authors.map(author => [
          #author.name \
#author.affiliation \
#link("mailto:" + author.email)
        ]),
      )

      par(justify: false)[
        *Abstract* \
#abstract
      ]

    }
  )

  doc
}
```

## Отдельный файл [#separate-file]

В большинстве случаев шаблон задаётся в отдельном файле, а затем импортируется в документ. Так основной файл, в котором вы пишете, остаётся свободным от лишнего, а ваш шаблон легко переиспользуется. Создайте новый текстовый файл на панели файлов, нажав кнопку плюса, и назовите его `conf.typ`. Переместите определение функции `conf` в этот новый файл. Теперь вы можете получить к нему доступ из своего основного файла, добавив импорт перед правилом show. Укажите путь к файлу между ключевым словом `import` и двоеточием, затем назовите функцию, которую хотите импортировать.

Ещё одна вещь, которую вы можете сделать, чтобы применение шаблонов стало чуть более элегантным, — использовать метод [`.with`](/docs/typst/reference/foundations/function#definitions-with) на функциях, чтобы предварительно заполнить все именованные аргументы. Так вы можете избежать явного написания замыкания и добавления аргумента-содержимого в конец списка аргументов шаблона. Шаблоны на [Typst Universe](https://typst.app/universe) разработаны для работы с таким стилем вызова функций.

<TypstRender
  code={`
  #import "conf.typ": conf

  #set document(title: [
    A Fluid Dynamic Model for
    Glacier Flow
  ])

  #show: conf.with(
    authors: (
      (
        name: "Theresa Tungsten",
        affiliation: "Artos Institute",
        email: "tung@artos.edu",
      ),
      (
        name: "Eugene Deklan",
        affiliation: "Honduras State",
        email: "e.deklan@hstate.hn",
      ),
    ),
    abstract: lorem(80),
  )

  = Introduction
  #lorem(90)

  == Motivation
  #lorem(140)

  == Problem Statement
  #lorem(50)

  = Related Work
  #lorem(200)
`}
  image="/typst_docs_assets/images/lwIj4TojpqcuDjEQOGFZoA.png"
  alt=""
  editable={true}
/>
