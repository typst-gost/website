## Таблицы [#tables]

- Таблицы стали _гораздо_ более гибкими; чтобы начать работу, прочитайте новое [руководство по таблицам](/docs/typst/guides/tables)
- Добавлен элемент [`table.cell`](/docs/typst/reference/model/table#definitions-cell) для настройки отдельных ячеек
- Ячейки теперь могут занимать несколько [столбцов](/docs/typst/reference/model/table#definitions-cell-colspan) или [строк](/docs/typst/reference/model/table#definitions-cell-rowspan)
- Теперь можно настраивать [обводку](/docs/typst/reference/model/table#definitions-cell-stroke) отдельных ячеек
- Аргументы [`align`](/docs/typst/reference/model/table#parameters-align) и [`inset`](/docs/typst/reference/model/table#parameters-inset) функции table теперь также принимают функции `(x, y) => ..`
- Добавлены [`table.hline`](/docs/typst/reference/model/table#definitions-hline) и [`table.vline`](/docs/typst/reference/model/table#definitions-vline) для удобной настройки линий
- Добавлен элемент [`table.header`](/docs/typst/reference/model/table#definitions-header) для заголовков таблиц, повторяющихся на каждой странице
- Добавлен элемент [`table.footer`](/docs/typst/reference/model/table#definitions-footer) для нижних колонтитулов таблиц, повторяющихся на каждой странице
- Вся новая функциональность таблиц также доступна для [сеток](/docs/typst/reference/layout/grid)
- Исправлены ошибки, связанные с промежутками (gutter)

_Спасибо [@PgBiel](https://github.com/PgBiel) за его работу над таблицами!_

## Шаблоны [#templates]

- Теперь вы можете использовать пакеты шаблонов для начала работы над новыми проектами. Нажмите _Начать с шаблона_ на панели управления веб-приложения и выберите предпочитаемый шаблон или выполните команду `typst init <template>` в CLI. Вы можете [просмотреть доступные шаблоны здесь](https://typst.app/universe/search/?kind=templates).
- Переключение шаблонов после начала работы стало проще. Вы можете просто импортировать функцию стилизации из другого пакета шаблонов.
- Авторы пакетов теперь могут отправлять свои собственные шаблоны в [репозиторий пакетов](https://github.com/typst/packages). Поделитесь шаблоном для статьи, вашего учебного заведения или оригинальной работы, чтобы помочь сообществу быстрее приступить к своим проектам.
- Шаблоны и пакеты теперь организованы по категориям и дисциплинам. Фильтруйте пакеты по любой из таксономий в мастере _Начать с шаблона_. Если вы автор пакета, ознакомьтесь с новой документацией по [категориям](https://github.com/typst/packages/blob/main/docs/CATEGORIES.md) и [дисциплинам](https://github.com/typst/packages/blob/main/docs/DISCIPLINES.md).

## Контекст [#context]

- Добавлены _контекстные выражения:_ чтобы начать работу, прочитайте главу о [контексте](/docs/typst/reference/context)
- С помощью контекста вы можете получать доступ к настраиваемым свойствам, например `context text.lang` для доступа к языку, заданному через `set text(lang: "..")`
- Следующие существующие функции стали контекстными: [`query`](/docs/typst/reference/introspection/query), [`locate`](/docs/typst/reference/introspection/locate), [`measure`](/docs/typst/reference/layout/measure), [`counter.display`](/docs/typst/reference/introspection/counter#definitions-display), [`counter.at`](/docs/typst/reference/introspection/counter#definitions-at), [`counter.final`](/docs/typst/reference/introspection/counter#definitions-final), [`state.at`](/docs/typst/reference/introspection/state#definitions-at) и [`state.final`](/docs/typst/reference/introspection/state#definitions-final)
- Добавлены контекстные методы [`counter.get`](/docs/typst/reference/introspection/counter#definitions-get) и [`state.get`](/docs/typst/reference/introspection/state#definitions-get) для получения значения счётчика или состояния в текущем контексте
- Добавлена контекстная функция [`here`](/docs/typst/reference/introspection/here) для получения [расположения](/docs/typst/reference/introspection/location) текущего контекста
- Функция [`locate`](/docs/typst/reference/introspection/locate) теперь возвращает расположение уникального совпадения селектора. Её прежнее поведение заменено контекстными выражениями и временно доступно только для совместимости.
- Методы [`counter.at`](/docs/typst/reference/introspection/counter#definitions-at) и [`state.at`](/docs/typst/reference/introspection/state#definitions-at) теперь более гибкие: они напрямую принимают любой вид [locatable](/docs/typst/reference/introspection/location#locatable)-селектора с уникальным совпадением (например, метку), а не только расположения
- Когда контекст доступен, [`counter.display`](/docs/typst/reference/introspection/counter#definitions-display) теперь напрямую возвращает результат применения нумерации вместо непрозрачного содержимого. Его больше не следует использовать без контекста. (Планируется устаревание)
- Функцию `state.display` больше не следует использовать, вместо неё используйте [`state.get`](/docs/typst/reference/introspection/state#definitions-get) (Планируется устаревание)
- Аргумент `location` функций [`query`](/docs/typst/reference/introspection/query), [`counter.final`](/docs/typst/reference/introspection/counter#definitions-final) и [`state.final`](/docs/typst/reference/introspection/state#definitions-final) больше не следует использовать (Планируется устаревание)
- Аргумент `styles` функции `measure` больше не следует использовать (Планируется устаревание)
- Функцию `style` больше не следует использовать, вместо неё используйте контекст (Планируется устаревание)
- Правильный контекст теперь также предоставляется в различных других местах, где он доступен, например в правилах show, обратных вызовах компоновки и функциях нумерации в оглавлении

## Стилизация [#styling]

- Исправлен приоритет нескольких [правил show-set](/docs/typst/reference/styling#show-rules): теперь они применяются в том же порядке, что и обычные правила set
- Правила show-set для одного и того же элемента (например, `show heading.where(level: 1): set heading(numbering: "1.")`) теперь работают правильно
- Установка свойств элемента внутри трансформационного правила show (например, `show heading: it => { set heading(..); it }`) больше **не** поддерживается (ранее она тоже работала лишь иногда); вместо этого используйте правила show-set **(Обратно несовместимое изменение)**
- Текстовые правила show, которые совпадают со своим собственным выводом, теперь работают правильно (например, `` show "cmd": `cmd` ``)
- Элементы, передаваемые в правила show и возвращаемые запросами, теперь содержат все поля соответствующих функций элементов, а не только отдельные
- Все настраиваемые свойства теперь можно использовать в селекторах [where](/docs/typst/reference/foundations/function#definitions-where)
- Селекторы [and](/docs/typst/reference/foundations/selector#definitions-and) и [or](/docs/typst/reference/foundations/selector#definitions-or) теперь можно использовать с правилами show
- Ошибки в правилах show и контекстных выражениях теперь игнорируются во всех итерациях интроспекции, кроме последней, в соответствии с поведением старой функции [`locate`](/docs/typst/reference/introspection/locate)
- Исправлена ошибка, из-за которой правила set документа допускались после содержимого

- Исправлены различные случаи, когда функция [`hide`](/docs/typst/reference/layout/hide) не скрывала своё содержимое должным образом
- Исправлено использование [`h`](/docs/typst/reference/layout/h) и [`v`](/docs/typst/reference/layout/v) в [стеках](/docs/typst/reference/layout/stack)
- Невидимое содержимое, такое как обновление счётчика, больше не будет принудительно создавать видимый блок только для себя

## Синтаксис [#syntax]

- Добавлена поддержка вложенных [шаблонов деструктуризации](/docs/typst/reference/scripting#bindings)
- Специальные пробелы (например, тонкие или неразрывные) теперь разбираются буквально, а не сворачиваются в обычные пробелы **(Обратно несовместимое изменение)**
- Корейский текст теперь может использовать синтаксис выделения без добавления пробелов **(Обратно несовместимое изменение)**
- Токен [`context`](/docs/typst/reference/context) теперь является ключевым словом и больше не может использоваться как идентификатор **(Обратно несовместимое изменение)**
- Вложенные строчные комментарии больше не допускаются в блочных комментариях **(Обратно несовместимое изменение)**
- Исправлена ошибка, из-за которой `x.)` трактовалось как доступ к полю
- Текстовые элементы теперь могут охватывать фигурные скобки в разметке
- Исправлен молча неверный разбор, когда имя функции заключено в скобки
- Исправлены различные ошибки при разборе шаблонов деструктуризации, массивов и словарей

- Добавлена поддержка передачи [входных данных](/docs/typst/reference/foundations/sys) через флаг CLI
- При передаче имени файла `-` Typst теперь будет читать ввод из stdin
- Теперь используется системная реализация TLS для сетевых запросов, что в целом должно быть более надёжным
- Режим наблюдения теперь правильно обнаруживает создание ранее отсутствовавшего файла
- Добавлен флаг `--color` для настройки того, печатать ли цветной вывод
- Исправлен user agent, с которым загружаются пакеты
- Встроенные шрифты обновлены до новейших версий

## Разработка [#development]

- Добавлен флаг `--vendor-openssl` в CLI для настройки того, следует ли связывать OpenSSL статически вместо динамически (не применимо к Windows и платформам Apple)
- Удалён старый флаг трассировки (и её подробности) из CLI
- Добавлен новый флаг `--timings`, который заменяет старое профилирование в виде flamegraph в CLI
- Добавлен минимальный CLI в крейт `typst-docs` для извлечения документации языка и стандартной библиотеки в формате JSON
- Аргумент `ident` функции `typst_pdf::export` изменён с `Option` на `Smart`. Его следует устанавливать в `Smart::Custom`, только если вы можете предоставить стабильный идентификатор (как это может делать веб-приложение). CLI устанавливает `Smart::Auto`.
